## 一、排行榜用户主页（他人主页）

### 1.1 需求
排行榜中点击任意用户，进入其公开主页，可查看：
- 基本信息：头像、昵称、slogan（若 users 表无此字段则新增）、勋章总数、加入时间
- 足迹：该用户已收集的 POI（地图打点 + 列表）
- 勋章：他人视角的勋章墙（复用 MedalWall，支持 solo/pk 过滤）
- **不展示对局列表**（已确认）

### 1.2 确认的决策
- **隐私开关**：用户可关闭"公开主页"；关闭后排行榜昵称不可点击，直连主页 URL 提示"该用户已隐藏主页"。默认公开。
- **接口形态**：复用现有接口扩展 `user_id` 参数（改动最小），前端多请求几次，不做单一聚合接口。
- 路由直接使用 user_id（`/user/:id`），不做防遍历 token。
- **足迹坐标不脱敏**：精确坐标直接展示（已确认，鼓励认识地点，不怕"剧透"）。

### 1.3 现状基础
- 排行榜 `Leaderboard.tsx`（行增加点击跳转）；勋章墙 API `GET /api/medal/wall`（已支持按用户查询）
- 足迹 API `GET /api/collection/tracks` 需扩展 `user_id` 参数
- 对局记录 `GameRecord` 字段齐全，需新增按用户查询的公开 API

## 二、反馈回复 + 我的投稿

### 2.1 需求
后台可回复用户反馈；用户端在反馈表单下方新增**「历史反馈与回复」**列表（本人历史反馈 + 官方回复）。同理，投稿页面新增**「我的投稿」**列表（含投稿状态：待审核/已通过/未通过）。

### 2.2 确认的决策
- 暂不做消息/通知系统，仅列表展示，时间倒序。
- `Feedback` 表新增：`admin_reply`（TEXT）、`replied_at`、`replied_by`；后台反馈管理加回复输入框与"已回复/未回复"筛选。
- 「历史反馈与回复」归属口径（已确认）：登录用户按 user_id、游客按 session_id 匹配，**同一用户两种身份数据需合并展示**。
- 「我的投稿」同时展示纠正记录（见下节），状态与投稿一致。

## 三、POI 纠正功能

### 3.1 需求
用户对已有 POI 提交纠正建议。纠正**不直接修改** POI 任何字段，提交时将建议内容**另存为一张纠正快照表**的记录；后台审核**采纳后**才将该快照写回 POI。入口：
1. "我的足迹"中每个足迹点的详情操作
2. 各对局结束界面结算面板底部统一小按钮（图标 + "纠正"，低调不打扰）——自由模式、PK 模式、专题点选、专题巡航全覆盖

### 3.2 确认的决策
- 新建独立表 `poi_corrections`（不复用 POISubmission），字段包含：`poi_id`、提交人（用户或匿名 session_id）、**纠正快照**（建议的名称/分类/坐标/形状范围完整快照，JSON 或分字段）、`status`（pending / adopted / rejected）、`created_at`、`adopted_at`。
- **允许匿名提交**（与投稿策略一致）。
- 前端复用 `Contribute.tsx` 表单：`mode=correction&poiId=xxx` 进入，预填 POI 当前值，文案"纠正此地点"。
- 后台审核：原 POI 数据 vs 纠正快照对照视图；采纳 = 快照整体写回 POI；拒绝则仅存档。
- 纠正状态在「我的投稿」列表中可见。
- **采纳反馈（已确认）**：纠正被采纳后，提交者打开「我的投稿」时该条以醒目"已采纳"状态标识展示；不做推送通知。

### 3.3 现状基础
- 结算面板位置：`Game.tsx`（`result` 状态）、`PKGame.tsx`、`Collection.tsx`（单点结束 + 总结束两处）
- 足迹：`Tracks.tsx` → `GET /api/collection/tracks`

## 四、分期实施计划（小步快跑，每期独立上线验证）

> 原则：一次只上一期，线上验证确认无问题后再进行下一期；每期均可增量部署，不改动现有路由文件。

### 第一期：反馈回复 + 我的投稿（改动最小，先行验证链路）
- 后端：`Feedback` 表加 `admin_reply / replied_at / replied_by`；新增「历史反馈与回复」「我的投稿（仅投稿状态）」两个查询接口
- 后台：反馈管理加回复输入框与"已回复/未回复"筛选
- 前端：反馈表单下方加历史列表；投稿页加「我的投稿」列表
- 验证点：后台回复后用户端可见；游客/登录身份数据合并展示正确

### 第二期：POI 纠正（新表 + 新入口，依赖第一期的「我的投稿」）
- 后端：新建 `poi_corrections` 表；提交接口（允许匿名）；采纳写回 POI；状态查询并入「我的投稿」
- 前端：复用投稿表单（`mode=correction&poiId=xxx`，预填当前值）；足迹详情 + 四类对局结算面板底部小按钮
- 后台：原值 vs 纠正快照对照审核视图；"已采纳"状态醒目标识
- 验证点：提交→审核→采纳写回全链路；结算面板按钮不干扰原结算流程

### 第三期：开发计划公示 + 用户评价（原第四期，方案详见第五章）
- 后端：新建 `dev_plans`（开发计划）+ `dev_plan_feedbacks`（用户评价）两张表；后台计划增删改接口（保存即用户可见）；评价提交（无门槛、同设备覆盖式一条）与公开查询接口
- 后台：新增「开发计划」管理 Tab（标题/内容/三态状态/排序 + 评价查看，评价全员可见，无需审核视图）
- 前端：首页与「意见留言」并列的「开发计划」按钮 + 弹窗（计划卡片、👍/👎 计数、文字反馈 + 附图最多 3 张、评价列表全员可见）
- 验证点：后台保存后用户端可见；同设备覆盖式评价生效；计数与评价列表全员一致

### 第四期：排行榜用户主页（原第三期）

## 五、开发计划公示与评价（第三期详细方案）

### 5.1 需求与确认口径（2026-08-30）
后台可编写"开发计划"（接下来要做什么），**保存即对用户可见**；用户端查看计划并以 **👍/👎 + 文字反馈 + 附图** 进行评价；**评价内容与点赞点踩计数对所有用户及后台可见**。口径要点：
- 评价无门槛，允许匿名（与意见反馈一致，按 session_id）
- 同一设备对同一计划仅一条评价，可修改覆盖，也可撤回（撤回后用户端不可见，后台保留记录；撤回后可重新评价）
- 后台可删除违规评价（评价全员公开，防恶意内容）
- 评价不做审核、不做通知；三种计划状态均可评价

### 5.2 方案设计（定稿）
```sql
-- 开发计划（后台填写保存即用户可见，无草稿态）
dev_plans:
  id, title (String 128), content (Text),
  status (String 20: planning/done/abandoned → 计划中/已上线/已放弃, 默认 planning),
  sort_order (Int, 默认 0), created_at, updated_at

-- 用户评价（👍/👎 两档；同设备一条，覆盖式更新；全员可见）
dev_plan_feedbacks:
  id, plan_id (FK dev_plans.id, index),
  session_id (String 64, index),        -- 无门槛匿名评价（与意见反馈口径一致）
  nickname (String 50 nullable),        -- 称呼（可选，公开展示）
  attitude (String 10: like/dislike),
  comment (String 256 nullable),        -- 文字反馈（选填）
  images (Text nullable),               -- 附图 JSON 数组，最多 3 张（OSS，复用现有上传接口）
  withdrawn_at (DateTime nullable),     -- 用户撤回时间（撤回后用户端不可见，后台保留存档）
  created_at (index), updated_at,
  UNIQUE KEY (plan_id, session_id)
```
- 接口：公开 `GET /dev-plans`（列表，含 👍/👎 计数、评价总数、本人态度）、`GET /dev-plans/{id}/feedbacks`（评价列表，全员可见，不含已撤回）、`POST /dev-plans/{id}/feedback`（提交/覆盖，无门槛；已撤回的重新提交自动恢复）、`POST /dev-plans/{id}/feedback/withdraw`（撤回本人评价，软撤回置 withdrawn_at）
- 后台接口：`GET/POST/PUT/DELETE /admin/dev-plans`；`DELETE /admin/dev-plan-feedbacks/{id}`（删除违规评价，物理删除）
- 附图上传复用现有 `POST /api/upload`（意见反馈同款）

### 5.3 交互设计（定稿）
- **入口**：首页与「意见留言」并列的「开发计划」按钮，弹窗展示
- **计划展示**：卡片式列表（sort_order 降序）；状态徽标三态：`计划中` / `已上线` / `已放弃`；三种状态均展示、均可评价
- **评价形式**：👍 / 👎 两档快评 + 文字反馈（选填，≤256 字）+ 附图（可选，最多 3 张，OSS 上传，复用意见反馈上传）；同设备已有评价时预填本人评价进入修改
- **可见性**：评价文字/图片、点赞点踩数量对所有用户可见（后台同样可见）；未填称呼的评价展示为"路人"
- **评价列表**：时间倒序，分页加载，不含已撤回评价
- **撤回**：本人评价处提供"撤回"入口，撤回后用户端立即不可见、计数减一；后台保留"已撤回"存档记录；撤回后可重新评价（覆盖原记录并恢复展示）
- **后台管理**：计划卡片显示 👍/👎 计数与评价总数；每条评价带删除按钮（二次确认，物理删除，防恶意内容）
- **通知**：不做

### 5.5 复查结论（2026-08-30 第二轮反馈，已全部定稿）
1. **后台删除评价**：支持（公开信息防恶意评论）→ 已并入 5.2 / 5.3
2. **"已放弃"计划**：不区分，三态均可评价 → 已并入 5.1 / 5.3
3. **用户撤回评价**：支持；撤回后后台保留存档 → 已并入 5.2 / 5.3

> 其余无待确认项。风险备注：同设备一条限制可被多设备绕过刷评，暂不做 IP 限制，出现刷评再补。
