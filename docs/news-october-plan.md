## 三、开发方案

### 3.1 数据模型（新增 3 表，独立于勋章/专题体系）

```
news_timelines        新闻时间线（玩法单元）
  id / code(unique) / name / description / color / cover_url
  batch("2026-10") / sort_order / audit_status(pending|approved)
  enabled / created_at

news_pois             新闻事件点
  id / timeline_id FK / name / event_date("2026-10-01")
  event_text(事件简介) / fact_text(地理冷知识) / hint_text(不剧透提示)
  link_url(报道外链,可空) / link_source(媒体名) / link_checked_at
  lng / lat / region / difficulty(1-5) / cover_url / sort_order / verified(bool)

news_progress         找点进度（游客/用户双轨）
  id / session_id / user_id(可空) / timeline_id / poi_id
  found_at / found_lng / found_lat
  UNIQUE(session_id, poi_id)
```

- news_pois 不复用 `pois` 表：pois 面向玩法池（含 source/category/难度池），新闻点无玩法属性，避免互相污染；关联 `CollectionPoi`/`Medal` 体系不使用（对齐主方案"与勋章体系剥离"）。
- 审核沿用现有简化机制：录入默认 pending → 开发者审核 approved → 修改需重新审核。
- 迁移需等待 DDL 完成后再启动后端（create_all 冲突惯例）。

### 3.2 后端（`app/api/news.py` + `app/services/news.py`）

- `GET /api/news/timelines`：时间线列表 + 当前进度概览（session/user 识别复用现有会话机制）。
- `GET /api/news/timelines/{id}`：详情；未找到的点仅返回 hint/日期/序号，不返回 name、坐标、简介、链接（防剧透）。
- `POST /api/news/timelines/{id}/found`：入参 poi_id + 命中坐标，找点判定阈值复用现有找点逻辑；命中写入 news_progress，返回下一事件。
- `GET /api/news/timelines/{id}/summary`：全部找齐后返回完整时间线回顾 + 各点外链。
- 外链白名单校验（新华网/人民网/中新网等），失效链接靠 link_checked_at 巡检（N4：失效后仅保留简介）。

### 3.3 前端
