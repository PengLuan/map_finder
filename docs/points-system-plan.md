# 地图寻踪 · 用户体系与积分系统方案

> 状态：方案文档（不改代码）
> 范围：用户身份、积分获取、**积分消费**（重点）、经济平衡、分阶段落地
> 现状参考：`admin-and-ugc-plan.md`（player_sessions 已采集）、`hard-mode-difficulty-reflection.md`（6.2 可选救济、8.2 变现工具箱已留接口）

---

## 一、背景与目标

### 1.1 现状
- 无登录体系，玩家靠 `session_id` + IP 识别，换设备/清缓存即丢失身份
- 已有 `player_sessions` 表记录对局行为，但无法跨设备归并到同一玩家
- `hard-mode-difficulty-reflection.md` 已明确"变现先靠 100 个真爱用户，小额付费 + 激励广告 + 比赛 + B 端引流"的路径，但缺少**统一货币**承载

### 1.2 目标
1. 用**邮箱绑定**作为最小登录成本，让积分可跨设备留存
2. 各种行为产生积分，让玩家有"我留下了东西"的归属感
3. **重点**：找到足够多、足够自然的积分消费场景，让积分有去处、有渴望、有复玩动力
4. 为后续变现（广告抵扣、小额付费、赛事报名）预留同一套货币接口

### 1.3 设计原则
- **不卖数值 / 不卖权力**（`hard-mode-difficulty-reflection.md` 8.2 红线）：积分不能买胜率，只能买便利/外观/特权
- **绑定邮箱本身也奖励积分**：身份建立即发"开户礼"
- **匿名玩家也能攒分但不可留存**：制造"绑定才不丢失"的转化动机
- **消费场景优先于获取场景**：先有"想花的地方"，发分才有意义

## 二、用户身份体系

### 2.1 身份层级

| 层级 | 标识 | 能力 | 积分留存 |
|------|------|------|---------|
| 游客 | `session_id` + IP | 正常游玩、攒当次积分 | ❌ 换设备即丢 |
| 绑定邮箱用户 | `email` + 密码 / 验证码登录 | 跨设备积分同步、参与排行榜、UGC 投稿署名 | ✅ 永久 |
| 管理员 | `ADMIN_TOKEN`（已存在） | 后台管理 | — |

### 2.2 邮箱绑定的设计

**为什么是邮箱而不是手机号/微信**：
- 邮箱无实名成本、无运营商依赖、隐私压力小，适合 niche 地理爱好者群体
- 微信服务号已有（joy_word 项目），但 map 项目暂无公众号绑定必要，邮箱足够
- 后续如需更强身份，可在邮箱基础上叠加微信/手机号，不冲突

**绑定流程**：
1. 首页右上角"👤 我的" → 弹窗"绑定邮箱领取 500 积分开户礼"
2. 输入邮箱 → 后端发 6 位验证码（已有邮件能力的项目可复用，无则用 SMTP）
3. 输入验证码 → 绑定成功
4. 匿名期攒的积分按 `session_id` 合并到邮箱账户（关键：避免"绑了就白攒"的负面体验）

**未绑定玩家的转化钩子**：
- 每局结算时若积分 > 阈值（如 200）且未绑定，结算页提示"你本局获得 X 积分，绑定邮箱后才能永久保留并累计"
- 排行榜只展示绑定用户，匿名玩家想上榜必须绑定
- UGC 投稿需绑定邮箱（防滥用 + 署名需要）

### 2.3 数据模型扩展

`player_sessions` 已存在，新增 `users` 与 `point_ledger` 两表：

```sql
CREATE TABLE users (
  id            BIGINT PRIMARY KEY AUTO_INCREMENT,
  email         VARCHAR(128) NOT NULL UNIQUE,
  password_hash VARCHAR(128) NULL COMMENT '可选密码，NULL 表示仅验证码登录',
  nickname      VARCHAR(32)  NULL,
  avatar_url    VARCHAR(512) NULL,
  total_points  INT          DEFAULT 0 COMMENT '当前可用积分余额',
  lifetime_points INT        DEFAULT 0 COMMENT '历史累计积分（不可减）',
  created_at    DATETIME     NOT NULL,
  last_login_at DATETIME     NULL,
  INDEX idx_email (email)
);

CREATE TABLE point_ledger (
  id          BIGINT PRIMARY KEY AUTO_INCREMENT,
  user_id     BIGINT      NOT NULL,
  delta       INT         NOT NULL COMMENT '正=获取，负=消费',
  reason      VARCHAR(32) NOT NULL COMMENT '见 §3/§4 的 reason 枚举',
  ref_id      VARCHAR(64) NULL COMMENT '关联 session_id / room_id / submission_id',
  balance_after INT       NOT NULL COMMENT '本次变更后余额（便于审计/对账）',
  created_at  DATETIME    NOT NULL,
  INDEX idx_user (user_id, created_at),
  INDEX idx_reason (reason)
);

-- player_sessions 新增外键
ALTER TABLE player_sessions
  ADD COLUMN user_id BIGINT NULL,
  ADD INDEX idx_user (user_id);
```

- `total_points` 可减（消费），`lifetime_points` 只增（成就指标）
- `point_ledger` 是唯一可信账本，余额变更必须落账，禁止直接 UPDATE `total_points`

## 四、积分消费场景（重点）

> 设计思路：把 `hard-mode-difficulty-reflection.md` 已规划的"可选救济 / 变现工具箱"全部接到积分货币上，让积分成为游戏内唯一的"购买力"。同时新增内容/外观/特权层，制造持续的消费渴望。

### 4.1 对局内救济（消耗品，最高频消费口）

直接复用 `hard-mode-difficulty-reflection.md` 6.2 的"可选救济"，改为**积分消耗**：

| 救济项 | reason | 消耗 | 作用 | 设计意图 |
|--------|--------|------|------|---------|
| 省份提示 | `hint_province` | -10 | 显示当前视野所在省份 | 新手坡道，不破坏签名挑战 |
| 坐标提示 | `hint_coord` | -20 | 显示目标相对方向的粗略指针 | 加速解码，不直接给答案 |
| 区域提示 | `hint_area` | -30 | 显示目标所在区域的矩形框 | 最强救济，慎用 |
| 加时 60 秒 | `extend_time` | -15 | 困难模式 / PK 倒计时延长 | 时间焦虑缓解 |
| 撤销上一步移动 | `undo_move` | -5 | 困难模式回到上一步视野中心 | 配合 `hard-mode-control-ux.md` 4.7 |
| 回到本轮起点 | `reset_origin` | -10 | 困难模式回到开局位置 | 敢于探索的保险 |

**关键平衡**：
- 困难模式"无救济通关"额外奖励 +30 积分（§3 `hard_pure_win`），让高手有"不用救济"的正反馈
- 救济**只在困难模式/单人有意义**；简单模式本就允许缩放，无救济入口
- PK 模式救济对双方独立计费，不影响公平（你用救济也得猜对才行）

### 4.2 内容解锁（持续渴望，鼓励主题探索）

| 解锁项 | reason | 消耗 | 说明 |
|--------|--------|------|------|
| 高级主题池 | `unlock_theme` | -300 | 部分硬核主题（5000m+山峰、各省极值、考古遗址）默认锁，需积分解锁一次永久 |
| 自定义主题组合 | `custom_theme_mix` | -100 | 选 2-3 个主题混合出题（如"名山+湖泊"） |
| 单局指定 POI 池 | `pinpoint_pool` | -50 | 一局内强制从某省某主题抽题（适合"我刷一周想练江苏湖泊"） |
| 隐藏彩蛋主题 | `unlock_easter` | -500 | 核电站/航天发射场等小体量"彩蛋题"，仅积分可解锁 |

**为什么是内容而不是功能**：内容解锁有"完成感"（解锁了就永远有），不像消耗品用完就没，适合长期攒分的目标。对 niche 玩家来说"解锁考古遗址主题"本身就是荣誉。

### 4.3 外观系统（荣誉层，纯装饰不卖数值）

直接对应 `hard-mode-difficulty-reflection.md` 8.2 "卖荣誉与表达"：

| 外观 | reason | 消耗 | 说明 |
|------|--------|------|------|
| 轨迹卡皮肤 | `skin_track` | -80 | 结算页轨迹回放的线条样式（霓虹/水墨/复古地图） |
| 标记图标皮肤 | `skin_marker` | -60 | 替换默认红色倒水滴（如金叶/青竹/古风朱砂） |
| 个人主页背景 | `skin_profile` | -120 | 个人主页底图（卫星图/地形图/古地图风格） |
| 昵称前缀称号 | `title_prefix` | -200 | 如"地理玩家·""探索者·"前缀，永久 |
| 结算页勋章展示位 | `medal_slot` | -150 | 个人主页最多展示 6 枚勋章，额外插槽需购买 |

**设计哲学**：所有外观**不影响任何判定**，纯表达自我。niche 玩家愿意为"我的轨迹卡和别人的不一样"付费，这是 `hard-mode-difficulty-reflection.md` 已验证的情绪资产。

### 4.4 UGC 投稿特权

| 特权 | reason | 消耗 | 说明 |
|------|--------|------|------|
| 每日额外投稿额度 | `ugc_quota` | -30/次 | 默认每日 5 条，超出按条扣分 |
| 优先审核通道 | `ugc_priority` | -50 | 投稿进快速审核队列（24h 内必处理） |
| 投稿免审白名单 | `ugc_trusted` | -2000 一次性 | 历史通过 ≥10 条且无驳回的用户可购买，投稿直接入库但仍可被后台撤回 |

**设计意图**：投稿本身奖励 +80，但"投得多/审得快"要消耗，制造投稿活跃用户的深度参与。免审白名单是高端荣誉 + 实用特权，定价高对应高门槛。

### 4.6 赛事与榜单（长线消费 + 变现接口）

| 场景 | reason | 消耗 / 奖励 | 说明 |
|------|--------|------------|------|

**关键**：赛事报名费是积分**最自然的黑洞**——玩家为荣誉付费，平台不收现金也完成了货币回收。后期叠加现金赛事时，把"积分报名"换成"现金报名"即可，架构无需改。

## 五、排名体系与段位系统

> 设计思路：多维榜单让不同类型玩家都有上榜机会——硬核玩家拼困难榜，主题爱好者拼主题榜，本地玩家拼省份榜，UGC 贡献者有专属榜。**榜单是积分消费的持续渴望源**（想上榜 → 想赢分 → 想用救济省时间），也是 niche 社区的"晒"舞台。

### 5.1 榜单维度矩阵

三个独立维度，按需组合，避免笛卡尔积爆炸：

| 维度 | 取值 | 数量 | 说明 |
|------|------|------|------|
| 时间 | 周 / 月 / 总榜 | 3 | 周/月榜定时结算，总榜滚动 |
| 区域 | 全国 / 大区 / 省份 | 1+7+34=42 | 大区按行政区划分组 |
| 主题 | 全主题 / 单主题 | 1+32=33 | 单主题对应 `poi-themes-plan.md` 32 主题 |
| 类型 | 综合 / 单人 / PK / 简单 / 困难 / 纯净挑战 / UGC | 7 | "纯净"=困难模式无救济通关 |

### 5.2 推荐榜单组合（P0/P1 优先级）

不做全笛卡尔积（3×42×33×7≈29000 个榜单无意义），精选有传播价值的核心榜单：

**总榜（P0，全局入口）**
| 榜单 | 时间窗口 | 指标 |
|------|---------|------|
| 全国综合榜 | 周/月/总 | 周积分增量 / 月积分增量 / `lifetime_points` |
| 全国单人榜 | 周/月 | 周积分（仅 solo 对局） |
| 全国 PK 榜 | 周/月 | 周积分（仅 pk 对局） |

**区域榜（P1，本地化竞争）**
| 榜单 | 时间窗口 | 指标 | 上榜门槛 |
|------|---------|------|---------|
| 大区榜（7 个） | 月 | 月积分增量 | 该大区对局 ≥20 局 |
| 省份榜（34 个） | 月 | 该省份相关 POI 胜场数 | 该省对局 ≥10 局 |

**主题榜（P1，鼓励深度探索）**
| 榜单 | 时间窗口 | 指标 | 上榜门槛 |
|------|---------|------|---------|
| 单主题榜（32 个） | 月/总 | 该主题完成 POI 数 / 主题累计积分 | 该主题完成 ≥10 POI |
| 主题征服榜 | 总 | 已通关主题数（≥50 POI 视为通关） | 至少通关 1 个主题 |

**类型榜（P1，差异化竞争）**
| 榜单 | 时间窗口 | 指标 | 设计意图 |
|------|---------|------|---------|
| 简单模式榜 | 月 | easy 模式胜场 | 新手榜 |
| 困难模式榜 | 月 | hard 模式胜场 | 高手榜 |
| 纯净挑战榜 | 月/总 | `hard_pure_win` 次数 | 无救济硬核荣誉 |
| UGC 贡献榜 | 月/总 | 投稿通过数 + 被玩次数 | 鼓励贡献 |

### 5.3 区域归属规则

玩家"属于哪个区域"需要明确，避免一人占多省榜：

- **绑定邮箱时自选家乡省份**（必填，1 个）：用于省份榜归属
- **大区自动按家乡省份映射**（如选江苏 → 自动归华东榜）
- **主题榜不按归属，按实际游戏发生地**：玩家在江苏榜也可参与"名山主题榜"，互不冲突
- **更换家乡省份**：每 90 天可改一次，避免反复横跳刷榜

### 5.4 段位系统

基于 `lifetime_points` 设计地理主题段位，所有段位**只升不降**（成就属性，与当前可用积分无关）：

| 段位 | 区间（累计积分） | 专属图标 | 解锁权益 |
|------|----------------|---------|---------|
| 探路者 | 0 – 1,000 | 默认水滴 | — |
| 测绘员 | 1,001 – 3,000 | 罗盘 | 解锁"标记图标皮肤"购买权 |
| 制图师 | 3,001 – 8,000 | 古地图 | 解锁"轨迹卡皮肤"购买权 |
| 地理学者 | 8,001 – 20,000 | 经纬仪 | 解锁"主题热力图"工具 |
| 地理大师 | 20,001 – 50,000 | 望远镜 | 解锁"GPX 导出"工具 + 专属称号前缀 |
| 地理宗师 | 50,000+ | 浑天仪 | 进入"宗师堂"专属展示页 + 限定徽章 |

- 段位是**权益门槛**：低段位玩家无法购买高段位外观/工具，制造"攒分升段"的动力
- 段位图标本身可作为外观皮肤展示在个人主页、PK 等待页、结算页

### 5.5 排名奖励

| 场景 | 奖励 | 频率 |
|------|------|------|
| 周榜前 10（全国综合） | 100–500 积分（见 §3） | 每周 |
| 月榜前 100（全国综合） | 限定称号"月度百杰" | 每月 |
| 省份月榜第 1 | 称号"{省份}首席"（如"江苏首席"） | 每月 |
| 主题月榜前 3 | 该主题专属徽章 | 每月 |
| 首次进入某段位 | 段位徽章（永久） | 一次 |
| 主题征服榜 +1 | "主题征服者"徽章 | 每次通关新主题 |
| 全 32 主题通关 | "全地理通"称号（极稀有） | 一次 |

### 5.6 防刷分（区域/主题榜专属）

| 风险 | 对策 |
|------|------|
| 刷省份榜（同 POI 反复赢） | 同一 POI 每日仅计 1 次胜场 |
| 主题榜刷量 | 主题内同 POI 仅计 1 次，必须不同 POI 才累加 |
| 区域归属刷榜 | 90 天内仅可改家乡一次 |
| 低门槛上榜（玩 1 局就第一） | 区域/主题榜均设最低对局数门槛（见 §5.2） |

### 5.7 排名展示

- **个人主页**：显示玩家在所有榜单的最佳名次（如"全国周榜 #23 / 江苏月榜 #1 / 名山主题榜 #5"）
- **首页榜单入口**：可切换"全国 / 我的省份 / 我的大区 / 我关注的主题"四个 tab
- **结算页**：本局结果若影响某榜单排名，toast 提示"你的江苏月榜排名上升 3 位"
- **PK 等待页**：显示双方段位图标 + 当前周榜排名，制造对抗张力

## 六、经济平衡

### 6.1 通胀控制

- **`total_points` 可减，`lifetime_points` 只增**：玩家历史成就是不可逆的，但当前余额受消费约束
- **消费场景必须有黑洞**：赛事报名费进入奖池后部分"销毁"（如 50% 进奖池、30% 销毁、20% 平台留存用于赛事奖品采购）
- **激励广告积分设日上限**：每日最多看 3 次得 45 积分，防止工作室刷分
- **UGC 投稿积分审核通过才发**：pending 状态不计分，rejected 不计分

### 6.2 防白嫖与防作弊

| 风险 | 对策 |
|------|------|
| 同邮箱多账号刷开户礼 | 同 IP 24h 内仅首个绑定邮件给 500 积分，后续绑定的同一 IP 标记风控 |
| PK 刷分（两人对刷） | PK 胜利积分需"非同 IP + 房间公开 + 有效移动距离 ≥ 阈值"才发放 |
| UGC 投稿刷分 | 投稿需绑定邮箱 + 每日上限 5 条 + 审核通过才发分 + 被驳回 3 次进入冷却 |
| 救济刷分 | 救济是消耗不是获取，天然不可刷 |
| 伪造邮箱 | 验证码 + 单邮箱 1 个账号 + 异常登录检测 |

### 6.3 定价校准（初版建议，需数据迭代）

以"新手首日预期获得"为锚：
- 首日新玩家典型路径：绑定 500 + 完成 3 局 15 + 胜 1 局 10 + 看广告 1 次 15 = **540 积分**
- 首日典型消费：省份提示 1 次 10 + 解锁主题折扣体验（首主题半价 150）= **160 积分**
- 净留：380 积分，有"攒了一笔"的体感，不至于首日就消费光

## 八、与现有变现路径的映射

| `hard-mode-difficulty-reflection.md` 工具 | 本文档对应场景 | 积分角色 |
|-------------------------------------------|----------------|---------|
| 小额付费：徽章/皮肤/赛季通行证 | §4.3 外观系统、§4.6 赛事 | 积分是免费版的"通行证"，现金是加速版 |
| 激励广告：看广告得提示/加时 | §4.1 救济 + §4.8 skip_ad | 积分与广告是等价货币，玩家可选 |
| 比赛：周榜/赛季 | §4.6 | 报名费黑洞 + 奖金池自循环 |
| B 端文旅引流 | §4.2 主题解锁 | 联名主题可作为"限定积分主题"引流 |

**核心原则**：积分是免费用户的购买力，现金是付费用户的加速器，两者**永不买同一份胜率**。

## 九、验收标准

1. 匿名玩家绑定邮箱后，原 `session_id` 下积分全部合并到邮箱账户，余额可见
2. 至少 6 个消费场景上线（救济 4 项 + 主题解锁 1 项 + 外观 1 项），每场景均有对应 `point_ledger` 记录
3. 防刷分：同 IP 24h 内绑定邮件超过 1 个时，第 2 个起不发开户礼
4. 7 日内绑定玩家平均消费积分 ≥ 50（验证消费场景被使用）
5. 周榜报名费进入奖池后，奖池分配规则透明可见，玩家可查询自身报名费去向
6. 至少 3 类榜单上线（全国总榜 + 省份榜 + 主题榜），个人主页可见自身在多榜的最佳名次
7. 段位系统生效：玩家 `lifetime_points` 跨段位边界时自动升级，并触发段位徽章发放
